# 2026-08-22: Agentic Armada inception

**Status:** accepted design baseline  
**Scope:** standalone private fleet-control-plane product

## Decisions recorded

- The product is named **Agentic Armada**. PFQE is an early consumer and a
  migration source, not a product dependency.
- Product records live under `.armada/`. The durable record is enforced through
  signed commits and append-only journal/ADR practice, not by folder name.
- Version 1 is a single active Mac-hosted control plane with PostgreSQL,
  backup/restore verification and a cold-standby recovery procedure.
- The implementation target is .NET 10/C#, with ASP.NET Core, gRPC/protobuf
  and Aspire for local development only. Domain logic follows an immutable,
  functional-core/tagless-final port model.
- Version 1 serves one private organisation but uses named principals, RBAC and
  an organisation boundary from the start.
- Signed OPA/Rego policy bundles govern admission; a typed, immutable
  node-side enforcement kernel retains hard capability limits.
- PostgreSQL current state is CAS-protected with `resourceVersion`; an
  append-only ledger and transactional outbox provide audit and replay.
- Content-addressed evidence is retained as immutable release assets in a
  dedicated private GitHub evidence repository. GitHub remains non-authoritative
  for scheduling, leases and state.
- Major Domo and Issue Masters operate autonomously within a signed workload
  capability envelope, including child-session control.

## Prototype lessons retained

The PFQE prototype correctly identified lease binding, durable ownership,
evidence hashes, strict protocol pinning and exact blocker reports as necessary
controls. It also demonstrated why GitHub polling, comments as locks and
session-local ownership cannot be the durable control plane. Armada retains
the controls and moves authority into a continuously reconciled API.

## Deferred decisions

Certificate/signing-key custody and recovery; GitHub evidence publication
credentials; the supported Copilot session-control interface; and the exact
backup target/restore drill are tracked as early ADRs. No live deployment may
proceed without their resolution and security review.
